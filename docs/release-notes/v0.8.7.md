# v0.8.7 — Standalone download of True Time Stop – fair Haste & Slow

Component 360, released in v0.8.6 as Time Stop and Haste effect clocks, is now
called True Time Stop – fair Haste & Slow, and it is also available as a
separate download. Its behaviour is unchanged: in a Time Stop the frozen
creatures' spell and item durations, delayed effects, poison, disease,
regeneration and repeated effects wait and continue after the stop with the
time they had left, and Haste and Slow no longer speed up or slow down
regeneration, poison, disease and repeated effects, while actions, attacks and
movement stay hasted or slowed. Its label, `cbr_time_stop_haste_clocks`, and its
two files stay the same.

- **Standalone download:** `CBR_TRUE_TIMESTOP-v0.8.7-windows.zip` is the same
  correction for BG2:EE and EET 2.7.3.0 games with EEex and without BG
  Rebalance. Extract it into the game folder and run
  `Setup-cbr_true_timestop.exe`. It makes the same checks as 360 and installs
  the same two files into `override`, the correction `CBRTC.lua` and its
  autoload `M_CBRTC.lua`; nothing else in the game is changed. Its README says
  how to check that it runs and how to uninstall it.
- **One installer at a time:** 360 now refuses to install while the standalone
  package is installed, and the package refuses while 360 is installed. Both
  install the same two files under the same names, so the game never loads the
  correction twice. v0.8.6's 360 does not check for the package yet; even then
  the correction loads only once.

Requirements, for 360 and the package alike: BG2:EE or EET on the 64-bit
2.7.3.0 executable, and EEex, installed before it; start the game through
InfinityLoader. The installer reads the executable's header and refuses every
other build, such as 2.6.6.0. Steam's and GOG's 2.7.3.0 executables are the
same file; Beamdog's build could not be compared and installs only if it is
that same file. The correction switches itself on at every game start. If
anything is unexpected, the game runs natively, and one line in
InfinityLoader's log says why; there is never a message in the game.

Install it before starting a playthrough; adding or removing it during one is
not supported. Saving during a Time Stop, and dispel, cure or death during one,
are not covered yet. No other component changed.

Automated checks: 787 tests, OK, 26 skipped (private captures) with WeiDU 249.
Among them, every installer test of 360 runs once more against the package, and
the guards are checked in both directions with the path forms WeiDU and mod
managers write. The package was tested in its own lab, a Steam BG2:EE 2.7.3.0
game with EEex 1.3.1 (LuaJIT) and no other mod. Installed from its archive by
its own setup, it switched the correction on at the main menu and corrected a
Time Stop, Haste, Slow, a cloud through a stop, walking and attacking, and a
save and reload; uninstalling put `override` back to its files from before. The
lab ran the package under its working name, before the rename; the two files
the game runs did not change. EET was not run with the package: EET runs the
same executable, the correction checks only the executable and EEex, the
installer's EET detection is covered by the automated tests, and in the full
CEBG stack on EET the same two files ran as 360. Beamdog's 2.7.3.0 build is
unverified. 360 has not been accepted in real gameplay yet.
